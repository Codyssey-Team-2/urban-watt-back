## 2. 모듈별 상세

### L1-① 공간 파이프라인 ⚙️

| 단계 | 내용 |
|---|---|
| 입력 | 세분류 토지피복, 비오톱, 법정동 경계 |
| 처리 | 전력소비시설(주거·상업·공공 등) 추출 → 버퍼 생성 → 피복 항목별 면적비 산출 |
| 출력 | `동코드 / 버퍼반경 / 불투수율 / 식생률 / 수면율 / 건물밀도` |
| 갱신 | 연 1회 (정적 자료) |
| 설계 포인트 | 버퍼 반경을 **하이퍼파라미터로 취급** — 50/100/200m 각각 모델을 돌려 성능이 가장 좋은 값을 선택하면 '임의값'이 '민감도 분석 결과'로 격상됨 |
| 🟦 격자 옵션 | 확장 단계에서는 버퍼 대신 **100m × 100m 격자 재격자화**로 전환 가능. 격자는 행정경계에 종속되지 않아 계통·생활권 단위로 재집계하기 쉬움. 단 전력 데이터가 법정동 단위이므로 **데모 단계에서는 버퍼 방식이 정합적** |

### L1-② 시계열 파이프라인 🔁

- 시간축 통일: 모든 소스를 **KST 정시(hourly)** 기준으로 재정렬
- S-DoT 이상치 규칙 **사전 명문화**: ASOS 대비 편차 임계 초과, 동일값 연속 고착, 물리 범위 이탈 → 제거 후 보간
- 전력 중복행 처리 규칙 문서화
- 파생 변수: 시간, 요일, 공휴일, CDD(냉방도일), 체감온도, 전일 동시각 lag, 3/24시간 이동평균

### L2 미기후 추정 모듈 ★

이 모듈이 **"S-DoT이 있는데 왜 토지피복이 필요한가"**라는 질문에 대한 답이다.

```
                  ┌──────────────┐
   ASOS 기온 ────▶│              │
   공간피처  ────▶│  ΔT 추정 모델 │────▶ 추정 국지기온 = ASOS + ΔT
   (불투수율 등)  │              │
                  └──────▲───────┘
                         │ 학습 라벨
                    S-DoT 실측 ΔT
```

- **데모**: 창신·진관은 S-DoT이 있으므로 실측을 그대로 사용
- **확장**: 학습된 관계로 센서 없는 동의 ΔT를 추정 → 서울 전역·타 도시 확장의 기술적 근거
- 이 구조가 있으면 S-DoT은 '보조 관측자료'가 아니라 **모델 학습 데이터**가 된다

### L3 수요 예측 엔진

**타깃 정의 원칙**

> 예측 타깃은 **실측 총 유효전력**으로 둔다.
> '냉방 민감 추가수요'는 예측 대상이 아니라 **기저수요 대비 잔차로 정의되는 분해 결과**이며, 냉방 민감도는 모델의 **해석 산출물**(온도 계수)로 제시한다.

→ 기온으로 만든 값을 기온으로 예측하는 **순환논리를 구조적으로 차단**한다.

**정규화 (필수)**

동별 규모 차이가 미기후 효과로 오독되지 않도록, 비교·시각화 단계에서는 다음 중 하나로 정규화한다.

1. **동별 기저수요 대비 상대 증가율(%)** ← 권장, 규모 문제를 원천 제거
2. 연면적당 사용량 (건축물대장)
3. 생활인구당 / 가구당

**모델 구성**

| 파트 | 역할 | 이유 |
|---|---|---|
| 선형 회귀 | 기온·CDD → 수요의 추세 | 트리 모델은 **학습 범위 밖을 외삽하지 못함**. 기록적 폭염에서 과소예측 방지 |
| GBM (XGBoost/LightGBM) | 선형 파트의 **잔차** 학습 | 시간대·요일 등 비선형 패턴 포착 |
| 분위수 회귀 | P50(중앙) / P90(상한) 동시 출력 | 경보는 '평균'이 아니라 '최악'을 봐야 함 |

**핵심 피처: 상호작용항**

정적 공간변수를 단독 투입하면 수학적으로 '동 ID 원핫'과 같아진다. 반드시 상호작용 형태로 넣는다.

```
불투수율 × 기온
식생률   × CDD
건물밀도 × 일사량
```

가설: *"같은 33℃라도 불투수율이 높은 동은 수요가 더 가파르게 증가한다"* — 즉 미기후는 수요의 **절대 수준이 아니라 온도 반응 기울기**를 바꾼다.

### L4 피크 위험 판정

- 임계치를 절대 전력량으로 잡으면 큰 동은 항상 위험, 작은 동은 항상 안전으로 나온다 → **동별 과거 분포의 상위 백분위**를 임계로 사용
- 판정 입력은 P50이 아니라 **P90 예측치** (경보는 보수적으로)
- 출력 3종: `위험등급` / `예상 초과 시각` / `리드타임(몇 시간 전 감지)`

### L5 서비스 계층 — 대시보드 4개 뷰

| 뷰 | 내용 | 시연 포인트 |
|---|---|---|
| ① 지도 뷰 | 동별 위험등급 색상 | 창신 vs 진관 색 차이가 한눈에 |
| ② 24시간 예측 | 실측·P50·P90·임계선 | 임계선을 P90이 뚫는 순간 = 경보 |
| ③ **모델 비교 뷰** | ASOS만 vs ASOS+미기후 | **프로젝트의 존재 이유를 증명하는 화면** |
| ④ 진단 뷰 | 동별 전환온도·온도민감도 계수 | "창신동은 24.5℃부터 냉방이 켜진다" |

## 3. 검증 프로토콜 (횡단축)

아키텍처와 함께 반드시 문서화해야 하는 부분이다.

| 항목 | 규칙 |
|---|---|
| **분할** | 시간 순서 기반. 랜덤 K-fold 금지(누수). 가장 더웠던 여름을 테스트셋으로 |
| **베이스라인** | ① 전일 동시각 persistence ② 요일×시간 평균 ③ ASOS만 사용한 GBM |
| **Ablation** | `ASOS만` vs `ASOS+미기후` — 동일 조건 비교. 결과는 **예비 결과**로 명시 |
| **LODO** 🟦 | Leave-One-Dong-Out. 학습에 없던 동에서의 성능 → 확장성 근거 |
| **지표** | RMSE·MAE(전체) + **여름 피크시간 가중 RMSE** + Precision·Recall·평균 리드타임(경보 관점) |
| **표기 원칙** | 모든 산출값에 `공식통계 / 프로젝트 예비값` 태그 부착 |

## 4. 확장 로드맵

| 단계 | 공간 단위 | 추가되는 것 |
|---|---|---|
| **1단계 (데모)** | 창신동·진관동 | 위 🟩 범위 전체 |
| **2단계** | 서울 전 법정동 | L2 ΔT 추정 모델 활성화, LODO 검증, 생활인구 결합 |
| **3단계** | 배전계통(변전소·뱅크) 단위 | 계통 데이터 연계 — 실제 운영 적용 |
| **4단계** | 미기후 격자 / 타 도시 | ENVI-met 등 3차원 시뮬레이션 결합 |

> **공간 단위에 대한 입장**: 법정동은 *공개데이터만으로 구성 가능한 최소 공간 단위*다. 실제 계통 부하 데이터는 비공개이므로 외부에서 접근할 수 없다. 즉 법정동 단위는 타협이 아니라 **외부 개발자가 도달할 수 있는 최대 해상도**이며, 운영기관 내부에서는 동일한 구조를 계통 단위에 그대로 적용할 수 있다.

## 6. 이 아키텍처가 방어하는 예상 질문

| 질문 | 아키텍처상의 답 |
|---|---|
| "S-DoT 있으면 토지피복 왜 필요?" | L2 — S-DoT을 **학습 라벨**로 써서 센서 없는 지역으로 확장 |
| "미기후 효과인지 동네 차이인지 어떻게 아나?" | L3 상호작용항 + 횡단축 Ablation |
| "그냥 두 동네 크기가 다른 거 아닌가?" | L3 정규화 (기저 대비 상대 증가율) |
| "기록적 폭염에도 맞나?" | L3 선형+GBM 하이브리드로 외삽 확보 |
| "평균 오차 말고 경보 성능은?" | L4 리드타임 + Precision/Recall |
| "법정동이 실무 단위인가?" | 4장 — 공개데이터 최대 해상도, 계통 단위 확장 구조 동일 |

## 7. 발표자료(PPT) ↔ 아키텍처 정합성 점검

### 7-1. ⛔ 최우선 — 성과 수치 슬라이드

현재 발표자료의 「정확도 개선 지표 시각화」에는 다음 수치가 확정적으로 제시되어 있다.

```
예측 오차 감소율   18.7% → 8.1%   (56% 감소)
피크 정보 적중률   72%   → 93%    (+21%p)
MAPE              14.3% → 6.2%   (57% 개선)
```

**이 수치는 프로젝트에서 아직 측정되지 않았다.** 팀의 Q&A 문서 Q10은 성능 개선 입증을 '향후 검증'으로 분류하고 있고, '피해야 할 표현' 표는 "미기후를 넣으면 정확도가 향상된다"를 금지 표현으로 지정하고 있다. 즉 **발표자료가 팀의 자체 검증 원칙을 정면으로 위반한 상태**다.

> 심사에서 "이 숫자는 어떻게 산출했나요?"는 반드시 나온다. 답하지 못하면 이 프로젝트가 쌓아온 데이터 정직성 전체가 한 번에 무너진다.

**대체 슬라이드 설계 (택1)**

| 안 | 제목 | 내용 |
|---|---|---|
| **A. 예비 결과** (권장) | "예비 성능 비교 (창신·진관, 2개 동)" | ASOS만 vs ASOS+미기후 실제 측정치. **하단에 "2개 동 예비 결과, 일반화는 향후 과제" 명시** |
| **B. 검증 설계** | "성능 검증 설계" | 베이스라인 4종 · Ablation · 평가지표(리드타임 포함)를 보여주고 "이렇게 검증할 것" |
| **C. 현상 근거** | "왜 초국소인가" | 창신·진관의 실측 야간 기온차 1.5℃ + 피복률 83% vs 35% — **측정된 사실만** 제시 |

A안이 가능하면 A, 시간이 없으면 C + B 조합. **어떤 경우에도 측정하지 않은 성능 수치는 넣지 않는다.**

### 7-2. 데이터 슬라이드에 S-DoT이 빠져 있음

현재 데이터 인벤토리 슬라이드는 `한전 / 기상청 수치예보 / 환경부 / 국토교통부 / 기타`로 구성되어 있으나,

- **S-DoT이 없다.** 프로젝트에서 가장 차별적인 자산(서울시 도시데이터 센서 실측 국지기온)이 발표에서 사라진 상태
- 기상 자료가 '수치예보'로 표기되어 있으나 실제 확보·사용 자료는 **ASOS 실측**
- 전력 데이터 출처가 '한전'으로 되어 있으나 실제 경로는 **서울 열린데이터광장(OA-22835)**

**수정안**

```
서울 열린데이터광장 ─ 법정동별 시간별 전력사용량 (OA-22835)
서울 열린데이터광장 ─ S-DoT 환경정보 (OA-15969)  ★ 국지 실측
기상청 ────────── ASOS 서울(108) 시간자료
기후에너지환경부 ── 세분류 토지피복지도 (EGIS)
서울 열린데이터광장 ─ 비오톱 생태현황도 · 법정동 경계
```

### 7-3. '미기후 대리변수' 정의가 슬라이드에서 다시 흔들림

AI 모델링 슬라이드의 입력 박스가 `온도 · 습도 · 복사 · 바람 · 지표특성`으로 되어 있다. 앞 네 개는 **기상 변수**이지 미기후 *대리변수*가 아니다. 이 표기대로면 프로젝트의 차별점인 공간정보가 도식에서 사라진다.

**수정안**

```
┌ 공간 대리변수 ┐   불투수피복률 · 식생피복률 · 수면율 · 건물밀도
┌ 국지 관측    ┐   S-DoT 기온·습도 (ΔT)
┌ 일반 기상    ┐   ASOS 기온·습도·풍속
┌ 과거 전력    ┐   법정동 시간별 사용량 · 계절성 · 요일성
        └──▶ 상호작용항 생성 (공간변수 × 기온) ──▶ 예측 엔진
```

### 7-4. '입증'이라는 단어

비교 슬라이드 제목이 "창신동 vs 진관동 비교를 통한 미기후 **영향력 입증**"이다. 2개 동으로는 입증이 성립하지 않으며, 팀의 Q&A 문서도 인과 표현을 피하기로 결정했다.

- 수정: **"창신동 vs 진관동 — 초국소 예측이 필요한 이유"**
- 하단 문구도 "필요성 입증" → **"필요성 확인"**
- +22% / +9% 수치도 실측값이 아니면 제거하거나 '예시'로 명시

### 7-5. 로드맵 연도

현재 1단계가 `~2025`로 표기되어 있으나 이미 지난 시점이다. **2026(현재) → 2027 → 2028~** 로 이동해야 한다. 3단계의 'EV·ESS 연동 실시간 피크 컷팅 자동 제어'는 Q14에서 직접 제어를 하지 않기로 결정한 부분이므로, **"제어 시스템에 예측값을 제공"**으로 표현을 낮추는 것이 문서 간 일관성에 맞다.

### 7-6. 오탈자

발표 직전 반드시 교정: 법절등→법정동, 정말하게→정밀하게, 용합→융합, 예축→예측, 가온→기온, 슴도→습도, 대리번수→대리변수, 회적화→최적화, 운업→운영, 에너저→에너지, 전역 확장→전역/전 지역 확장, "법정동 경제 기준"→"법정동 경계 기준".
